## 1. 需求背景

第一批已落地：皮肤系统内联在 `settings.html`（`skinMode` native/custom + `nativeSkin` light/dark/system + `skinColor{calendar,desktop,dock}` + `desktopFollowCalendar`/`dockFollowCalendar`），主进程 `recomputeTheme()`/`resolveBg()`/`resolveSkinState()`/`isDarkColor()` 做「生效主题 + 纯色背景 + 自动明暗」推导，透明度 `mainOpacity/desktopOpacity/dockOpacity` 散落在设置页各分区。

用户反馈要点（勿遗漏）：
1. **桌面插件算天数**：窗口外点击无法消除 range 状态（日历窗口已 OK）。
2. **日历窗口点外部收起**：时灵时不灵，只能再点浮动插件才收起。
3. **皮肤交互不对**：应为「设置里一个『皮肤设置』入口 → 弹出独立皮肤设置窗口」，窗口内先选界面（日历/浮动/桌面/放大），再针对该界面调 白天/黑夜/跟随系统/纯色/自选图片 + 透明度；桌面与放大默认跟随日历、可取消；浮动插件独立；每界面取景框比例不同；图片皮肤这次做完整。

## 3. 关键结论（拍板，供架构师直接采用）

> 以下为 team-lead 要求产品经理给出结论的 3 个点，均已拍板，勿再返回提问。

### 3.1 日历界面 vs 放大界面（同一 BrowserWindow 的 mini/max 两态）
- **透明度：窗口级共享。** `win.setOpacity()` 作用于整个 `BrowserWindow`，mini 与 max 共用同一窗口 → 透明度天然不可分。皮肤窗口「放大界面」页里的透明度滑杆与「日历界面」页是**同一个值**（UI 上两处显示同值、任一处拖动即同步）。数据上仍只有 `opacity.calendar` 一个值，不新增独立第四值。
- **皮肤背景（纯色/图片）：可分开。** 背景是渲染层 CSS 背景层，可按 `.max` 类（mini/max 态）切换不同背景变量；纯色/图片、取景/缩放均可独立。故日历界面与放大界面可分别设置不同的纯色或图片。
- **注意**：迷你与放大**等比**（`ASPECT = 340/430`，放大 `760×959`），故两者取景框**比例相同**（340:430），但取景位置/缩放/图片文件可不同。

### 3.2 图片背景下的文字明暗
- **默认「自动明暗」**：基于**取景框内图片区域**的平均亮度（沿用现有 WCAG 相对亮度判定 `isDarkColor` 思路，阈值 `lum < 0.5` → 深底浅字，否则浅底深字），与纯色皮肤判定一致。
- **提供手动覆盖**：每界面图片/纯色皮肤下，提供「文字明暗」三态——**自动 / 深字（浅底）/ 浅字（深底）**。默认「自动」。

### 3.3 皮肤选择器归属
- 皮肤配置从 `settings.html` 内联**迁出**，`settings.html` 仅保留一个「皮肤设置」入口按钮（放「功能区」顶部）；皮肤全部逻辑在独立 `skin.html`。

## 4. UI 交互说明

### 4.1 入口
- `settings.html` 功能区顶部新增 action-row 按钮「🎨 皮肤设置」→ `settings-action('open-skin')` → 主进程打开独立 `skin.html`（无边框透明卡片窗、表头 `-webkit-app-region: drag` 可拖动、`✕`/`Esc` 关闭，复用 `settings.html` 的窗口范式与设计 token）。

### 4.2 皮肤窗口布局（skin.html）
```
┌ 皮肤设置                        [✕] ┐
├─────────────────────────────────────┤
│ [日历界面] [浮动插件界面] [桌面插件界面] [放大界面] │ ← 顶部 4 界面分段
├─────────────────────────────────────┤
│ 当前界面：<选中界面名>                │
│ ── 皮肤类型 ────────────────────────  │
│  ( ) 白天   ( ) 黑夜   ( ) 跟随系统    │
│  ( ) 纯色   ( ) 自选图片              │
│ ── [仅纯色] 色盘：预设色板 + 取色器 ── │
│ ── [仅图片] 拖入图片区 + 取景/缩放 ──  │
│ ── [纯色/图片] 文字明暗：自动/深/浅 ── │
│ ── 透明度：滑杆 0.3~1.0 ──           │
│ [桌面/放大专属] ☑ 跟随日历界面        │
└─────────────────────────────────────┘
```

- 4 界面分段：`日历界面`（迷你）/`放大界面`（max）/`桌面插件界面`/`浮动插件界面`。单次选中一个，下方控件切换为该界面配置。
- **跟随开关（仅桌面/放大显示）**：默认 ☑ 勾选「跟随日历界面」；勾选时该界面除透明度外的所有控件**置灰**并显示「跟随日历界面」；取消勾选后控件解锁，并**以日历界面当前配置为初始值快照**（copy-on-write），用户在此基础上改。
- **浮动插件**：无跟随开关，独立配置。

### 4.3 5 种皮肤类型语义
| 类型 | 效果 |
|---|---|
| 白天 | 该界面用原生「白日」外观，无自选背景。 |
| 黑夜 | 该界面用原生「黑夜」外观，无自选背景。 |
| 跟随系统 | 该界面随系统深浅色**实时**切换原生外观（非仅启动检测）。 |
| 纯色 | 该界面用自选纯色作为**窗口背景层**；文字明暗可自动/手动。 |
| 自选图片 | 该界面用自选图片（含 GIF）作为**窗口背景层**；文字明暗可自动/手动。 |

### 4.4 色盘交互（纯色）
1. 选中「纯色」→ 展开色盘：预设色板（约 8~12 个低饱和中性/雅蓝/朱砂色块）+ 原生 `<input type="color">` 自定义取色。
2. 选色即时预览（对应界面背景色实时变化），关闭窗口即落盘。
3. 纯色 = 背景层，**不改变** `--accent`、状态色（`.range/.reminder/holiday`）与 DOM 结构（沿用第一批约束）。

### 4.5 图片皮肤交互流程（取景/缩放/GIF）—— 全新功能，交互规格

**导入**
1. 选中「自选图片」→ 显示取景区（比例随界面锁定）+ 「拖拽图片到此处」占位。
2. 拖拽图片文件进入（或点击选择文件）→ 支持 `png / jpg / jpeg / gif / webp`（GIF 支持动画）。
3. 导入后**立即复制**到 `userData/skins/`（文件名用 `{surface}_{时间戳}{原扩展名}` 消毒），后续读取只引用副本，用户可删除原文件。禁止引用原始绝对路径。

**取景框比例（每界面固定，不同）**
| 界面 | 窗口尺寸 | 取景框比例（宽:高） |
|---|---|---|
| 日历界面 | 340×430 | 340:430（竖，≈0.79） |
| 放大界面 | 760×959 | 340:430（与日历等比，`ASPECT` 锁定） |
| 桌面插件界面 | 340×370 | 340:370（≈0.92） |
| 浮动插件界面 | 116×50 | 116:50（极宽扁，≈2.32） |

**取景 / 缩放 / 拖动**
1. 图片以 `cover` 方式铺满取景框，超出部分被裁切。
2. **拖动**：按住图片平移，改变取景位置。
3. **缩放**：滚轮或滑杆缩放（范围 1×~5×），以取景框中心为锚点。
4. 取景结果存为**归一化 crop** `{x, y, w, h}`（0~1，相对原图）+ `zoom`，保证不同分辨率下复现一致。
5. 实时预览到对应界面窗口；每界面取景独立（切换 4 界面可分别取景）。

**GIF 动图**
- GIF 作为背景层时**保持动画播放**（渲染层 `<img>` 或 `background-image`，Chromium 原生支持，不依赖 `setBackgroundColor`）。
- 建议限制：单文件 ≤ 20MB、最长边 ≤ 4096px（超出提示，防止内存/CPU 失控，见 §7 待确认）。

**文字明暗（图片/纯色通用）**
- 默认「自动」：图片按取景框内平均亮度判定深浅（沿用 `isDarkColor` 相对亮度 < 0.5 逻辑，图片取采样点均值）。
- 可选手动「深字（浅底）」/「浅字（深底）」。

## 5. 数据模型变更

### 5.1 现状（第一批，将被替换）
```jsonc
{ "skinMode": "native|custom", "nativeSkin": "light|dark|system",
  "skinColor": {"calendar":null,"desktop":null,"dock":null},
  "desktopFollowCalendar": true, "dockFollowCalendar": true,
  "mainOpacity":1.0, "desktopOpacity":1.0, "dockOpacity":1.0 }
```

### 5.2 目标（第二轮）
```jsonc
"skin": {
  "surfaces": {
    "calendar": {
      "type": "light",              // light|dark|system|color|image
      "color": null,                // type=color: '#RRGGBB'
      "image": null,                // type=image: { file, crop, zoom }
      "text": "auto"                // auto|light|dark （color/image 生效）
    },
    "expanded": {
      "follow": "calendar",         // null=独立；默认 "calendar"（copy-on-write）
      "type": "light", "color": null, "image": null, "text": "auto"
    },
    "desktop": {
      "follow": "calendar",         // 默认 "calendar"
      "type": "light", "color": null, "image": null, "text": "auto"
    },
    "dock": {
      "type": "light", "color": null, "image": null, "text": "auto"   // 独立，无 follow
    }
  },
  "opacity": {
    "calendar": 1.0,                // mini+max 共享（同一窗口）
    "desktop": 1.0,
    "dock": 1.0
  }
}
```

```jsonc
// image 子对象
"image": {
  "file": "calendar_1700000000000.png",   // userData/skins/ 内文件名
  "crop": { "x": 0.2, "y": 0.1, "w": 0.6, "h": 0.8 },  // 归一化 0~1
  "zoom": 1.0
}
```

### 5.3 生效明暗（effective theme）推导规则（per-surface）
- 每界面独立推导「生效明暗」：`type=light→light`、`dark→dark`、`system→系统深浅`、`color/image→text 字段`（`auto` 由背景亮度推导，`light→浅底深字`、`dark→深底浅字`）。
- **非表面窗口**（托盘图标 / 关注列表 / 提醒弹窗 / 设置窗 / 皮肤窗自身）跟随**日历界面**的生效明暗作为基准主题。
- 主窗 mini↔max 切换时，渲染层按当前态（`.max`）应用 `calendar` 或 `expanded` 的生效明暗与背景层。

### 5.4 旧数据迁移（第一批 → 第二轮）
| 第一批字段 | 迁移目标 |
|---|---|
| `nativeSkin` | `surfaces.calendar.type`（同时同步为 expanded/desktop/dock 的初始 type，受 follow 约束） |
| `skinMode==='custom'` 且 `skinColor.calendar` 非空 | `surfaces.calendar.type='color'` + `color` |
| `skinColor.desktop`（`desktopFollowCalendar=false` 时） | `surfaces.desktop.type='color'` + `follow=null` |
| `skinColor.dock` | `surfaces.dock.type='color'`（**丢弃** `dockFollowCalendar`，浮动改独立） |
| `mainOpacity` | `opacity.calendar` |
| `desktopOpacity` | `opacity.desktop` |
| `dockOpacity` | `opacity.dock` |

## 6. 逐项验收标准（量化、可测）

- [ ] 图片皮肤持久化（file/crop/zoom），重启后复现同一取景。

### D · 透明度迁移
- [ ] 透明度从设置页各分区迁入皮肤窗口对应界面选择内。
- [ ] `日历界面`与`放大界面`透明度为**同一值**（窗口级共享），任一处调节另一处同步显示。
- [ ] 桌面/浮动透明度独立；语义沿用 `mainOpacity/desktopOpacity/dockOpacity`，扩展到放大界面即共享 `opacity.calendar`。

## 7. 待确认问题（产品已给出建议，供架构师/团队按需拍板）

1. **图片格式范围**：建议 `png/jpg/jpeg/gif/webp`（GIF 动画必须）。是否排除 webp？若为减小体积可仅 `png/jpg/gif`。
2. **图片体积上限**：建议单文件 ≤ 20MB、最长边 ≤ 4096px，超出时 toast 拒绝。是否接受该阈值，或需可配置。
3. **GIF 动画性能**：大 GIF 常驻背景的 CPU/内存风险，是否需要在「非激活/隐藏」时暂停动画（如 `visibility`/窗口隐藏时冻结）？建议：窗口隐藏时冻结动画帧。
4. **跟随的 copy-on-write 语义**：取消「跟随日历界面」时，建议以当前日历配置为初始快照。是否接受（而非回到默认「白天」）。
5. **纯色/图片与透明度的叠加**：建议图片/纯色背景之上仍可叠加窗口透明度（`setOpacity` 独立于背景层）。是否接受。
6. **`nativeSkin` 全局字段废弃**：第二轮改为 per-surface 后，旧 `nativeSkin`/`skinMode`/`skinColor` 字段是否保留兼容（避免老用户升级后设置丢失），还是直接迁移后删除。建议：保留一次性迁移逻辑，迁移后不再写旧字段。

## 8. 实现影响 / 迁移清单（给架构师与工程师）

- **settings.html**：移除内联皮肤选择器（`skinMode`/`nativeSkin`/各表面色盘/图片占位），改为「皮肤设置」入口按钮；保留 4 分区中非皮肤项。
- **新增 skin.html**：独立皮肤窗口，承载 4 界面选择 + 5 皮肤类型 + 色盘 + 图片取景 + 透明度 + 跟随开关。
