### 原始需求复述
- **调整 6 项**：① blur 隐藏偶发失效；② 算天数 range 状态在窗口隐藏后未重置；③ 浮动插件多屏位置漂移；④ 右键菜单取消后插件仍残留模糊；⑤ 放大界面顶部时间栏不可拖动；⑥ 浮动插件星期/日期间距放宽 + 上下内容居中。

## 2. 产品目标

1. **稳定性**：消除「点外部不消失 / range 状态残留 / 多屏位置漂移 / 右键模糊残留」四类既有的、用户可直接感知的体验缺陷，让桌面常驻挂件的交互可预期。
2. **皮肤可定制且不伤结构**：把「主题」升级为「皮肤」体系（原生：白日/黑夜/跟随系统；自选：纯色配色），并以**独立背景层**方式实现——不改变现有 UI 结构、状态色与核心逻辑。
3. **设置清晰化**：将设置弹窗重排为「功能区 / 桌面插件区 / 浮动插件区 / 日历窗口区」四分区，让皮肤、透明度、开关按作用对象就近归组，一眼定位。

## 3. 用户故事

- **As a** 多显示器用户，**I want** 浮动插件在每块屏幕上记住各自的位置，**so that** 外接屏断开再连后，插件能自动回到原位，而不是漂移到别处。
- **As a** 经常用「算天数」的用户，**I want** 隐藏日历后重新打开时不再残留上一次的选中区间，**so that** 每次算天数都从干净状态开始、不被历史选区误导。
- **As a** 追求个性化的用户，**I want** 给日历窗口、桌面插件、浮动插件分别设置纯色背景，**so that** 桌面整体观感贴合自己的审美，同时桌面插件默认跟着日历走、不用重复设置。
- **As a** 开启「跟随系统」的用户，**I want** 系统在深色/浅色间切换时日历实时跟随，**so that** 不需要重启或手动再切一次主题。
- **As a** 老花/放大模式用户，**I want** 放大后按住顶部时间栏也能拖动窗口，**so that** 拖动窗口不用刻意去找那条窄工具栏。

## 5. UI 交互说明

### 5.1 皮肤选择器结构（settings.html）

皮肤控制替换现有「主题」（白日/黑夜）分段控件，结构如下：

```
皮肤
├── 类型分段（二选一）：[ 原生皮肤 ] [ 自选皮肤 ]
│
├── 原生皮肤（type=原生时展开）
│   └── 三选一分段：[ 白日 ] [ 黑夜 ] [ 跟随系统 ]   ← 白日/黑夜单独列出，跟随系统为第三项
│
└── 自选皮肤（type=自选时展开，第一批仅纯色）
    ├── 日历窗口   [ 色卡 ]  ← 迷你与放大共用同一窗口，同一颜色
    ├── 桌面插件   [ 跟随日历 · 开关 ]  [ 色卡 ]   ← 默认开启跟随，开关打开时色卡置灰
    ├── 浮动插件   [ 色卡 ]
    └── 图片皮肤   [ 即将推出 ]（第二批，灰显占位）
```

- **生效主题与皮肤模式解耦**：`原生皮肤` 选项决定「当前生效主题」（白日/黑夜），`跟随系统` 由系统深浅色实时决定生效主题；`自选皮肤` 只覆盖各窗口**背景层颜色**，文字/状态色/布局仍沿用当前生效主题的 token。
- 任意选择**即时生效并持久化**（延续现有「无保存按钮、主进程为唯一真相」的交互范式，复用 `settings-set` 通道）。

### 5.2 色盘交互流程（自选纯色）

1. 设置页切到「自选皮肤」→ 显示 3 个表面色卡（日历窗口 / 桌面插件 / 浮动插件）。
2. 桌面插件色卡默认带「跟随日历」开关（开）且色卡置灰；关闭跟随后才可独立选色。
3. 点击某色卡 → 展开色盘：**预设色板**（约 8~12 个低饱和中性/雅蓝/朱砂系色块）+ **自定义取色**（原生 `<input type="color">`，零依赖、ES5 兼容）。
4. 选色过程中对应窗口背景色**实时预览**（主进程 `setBackgroundColor` 或 CSS 背景层变量下发）。
5. 关闭设置/切换皮肤类型即落盘；提供「重置为默认」恢复该表面为原生主题外观。
6. 纯色 = **窗口背景层**，不改动 `--accent` 强调色、状态色（`.range/.reminder/holiday` 等）与既有 DOM 结构。

### 5.3 设置页 4 分区布局

沿用 `settings.html` 现有 `section` 分组样式，仅重排归组（原「显示/窗口行为/窗口透明度/数据」四组 → 新的四分区）：

| 分区 | 归属项（建议） |
|---|---|
| **功能区** | 皮肤（原生/自选选择器）、开机自启、检查节假日更新 |
| **日历窗口区** | 日历窗口置顶、日历窗口自选配色（色卡）、日历窗口透明度 |
| **桌面插件区** | 桌面插件总开关、桌面插件跟随日历皮肤、桌面插件自选配色、桌面插件透明度、桌面插件锁定 |
| **浮动插件区** | 挂件条总开关、显示形态（插件/图标）、插件总在最前、浮动插件自选配色、浮动插件透明度 |

> 皮肤是全局外观，建议放「功能区」顶部；若后续觉得皮肤与「日历窗口」强相关，也可移入「日历窗口区」，此为待确认项（见 §7）。

### 5.4 皮肤数据模型（新增，最小侵入）

```js
// settings.json 新增字段（示意）
{
  "skinMode": "native" | "custom",            // 皮肤类型
  "nativeSkin": "light" | "dark" | "system",  // 原生皮肤选择（system=跟随系统）
  "skinColor": {                              // 自选纯色（十六进制，null=未设）
    "calendar": "#xxxxxx" | null,
    "desktop":  "#xxxxxx" | null,
    "dock":     "#xxxxxx" | null
  },
  "desktopFollowCalendar": true               // 桌面插件默认跟随日历皮肤
}
```

- 保留现有 `themeMode`（light/dark）作为**「生效主题」**：`nativeSkin==='light'|'dark'` 时直接等于它；`nativeSkin==='system'` 时由 `nativeTheme.shouldUseDarkColors` + `nativeTheme.on('updated')` 实时推导。
- 生效主题继续走既有 `theme-changed` 通道推送到主窗 / 浮动插件 / 桌面插件 / 关注列表 / 托盘，**复用不重造**。

## 7. 待确认问题

1. **「日历」与「放大日历」是否为同一表面？** 二者当前是同一个 `BrowserWindow`（mini/expanded 两种态），技术上无法给不同背景色。需求 B2 将二者并列为独立窗口。建议按「日历窗口（含迷你+放大）」作为一个配色表面处理，与 B3「日历窗口区」对齐——请确认。
2. **浮动插件是否也默认跟随日历皮肤？** 需求仅明确「桌面插件默认跟随日历皮肤」。建议浮动插件同样默认跟随（视觉统一），是否采纳请确认；否则浮动插件默认保持原生主题外观。
3. **「跟随系统」与「自选皮肤」的组合关系**：当 `skinMode=自选皮肤` 时，生效主题（白日/黑夜）来源是什么——沿用上次原生选择，还是自动跟随系统？建议：自选皮肤模式下仍可单独选「跟随系统/白日/黑夜」作为底色 token 来源，纯色只覆盖背景层。
4. **皮肤选择器归属分区**：本 PRD 建议皮肤选择器放「功能区」顶部，是否接受；或需独立成「外观」分区。
5. **色盘交互形态**：建议「预设色板 + 原生 `<input type="color">`」，是否满足需求（是否要求取色吸管 / 自定义 HEX 输入）。
6. **旧文档滞后**：`PROGRAM_SPEC.md` 头仍标注 v1.7.22、部分章节停留在 v1.7.x，与实际 v2.3.x 代码不符；建议本批完成后由工程师同步刷新文档（非本批功能，仅提示）。

## 8. 实现提示（给架构师/工程师，非强制）

- **A1/A2**：建议在 `electron-main.js` 主窗 `blur` 隐藏路径与 `hide()` 统一加一个「窗口已隐藏」IPC 下发（如 `win-hidden`），渲染层 `app.js` 收到即 `clearRange()`；blur 失效根因排查重点在 `suppressBlur` 的复位时机与 `dockWin/desktopWin.isFocused()` 的焦点竞态。
- **A3**：`screen` 已有 `display-metrics-changed` 越界纠正；多屏记忆需把单一 `dockBounds` 改为「按显示器 ID/边界为 key 的位置表」，并监听 `display-added/display-removed` 做恢复。
- **A4**：`dock.html` 的 `body.hit`（hover 高亮）在原生菜单弹出期间收不到 mousemove/mouseleave，菜单关闭后状态残留；建议在 `contextmenu` 及窗口 `blur` 时重置 `hitInside=false`、移除 `body.hit`、恢复穿透态。
- **A5**：`template.html` 给 `#infoBar` 增加 `-webkit-app-region: drag`（内部若有可点元素需 `no-drag` 排除）。
- **A6**：`dock.html` 日期文案拆为「星期 + 日期」两个 span，间距用 gap/margin 放宽；`#card` 保持 `justify-content: center` 垂直居中，注意不与 `applyDockSize()` 固定像素布局冲突。
- **B1/B2/B4**：皮肤以「独立背景层」实现——建议主进程用 `win.setBackgroundColor` + 渲染层背景变量（而非改 `--accent` 或 DOM 结构）；「跟随系统」用 `nativeTheme.on('updated')` 实时重算生效主题并走既有 `theme-changed` 广播。
