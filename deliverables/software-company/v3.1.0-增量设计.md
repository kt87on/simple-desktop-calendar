## 2. 冻结的契约（不得偏离）

### C1 · 原生风格 = 全局统一
- `dock` 纳入 follow 名单：`resolveSurfaceConfig()` 的判定由 `expanded/desktop` 扩展为 `expanded/desktop/dock`。
- `node 归一`：`dock` 也接受 `follow` 字段，**默认值 `'calendar'`**（新增数据与 v3.0.0 旧数据的迁移都落到这个默认）。
- 用户在皮肤窗点某个原生风格 → **只写 `skin-set('calendar','style',X)`**，其余跟随者自动跟着变。

### C2 · 手调后豁免
- `applySkinSet(surface, field, value)` 中，当 `surface ∈ {expanded, desktop, dock}` 且
  `field ∈ {style, bg, image, text, clarity, tone}` 且当前该 surface `follow === 'calendar'` 时：
  **先物化快照（等价于现有取消跟随的 copy-on-write 六项），置 `follow = null`，再应用本次写入。**
- `field === 'follow'` 的既有分支**保持不变**（显式取消 / 恢复跟随）。
- 写 `calendar` 永远不影响 `follow` 为 null 的界面。

### C3 · IPC 不新增
- 全程复用现有皮肤 IPC（`skin-get` / `skin-set`，含 surface 参数）与 `add-reminder`。
- **`preload.js` 预计无需改动**；若某工作流认为必须改，先回报 lead 再动。

### C4 · 自选图片弹窗 = 原皮肤窗全部"细调"能力的唯一去处
弹窗内需含：**界面选择器**（日历 / 放大窗口 / 桌面插件 / 浮动插件）、图片导入、背景来源（原生/图片）、明暗（浅/深/跟随系统）、UI 清晰度滑杆、深浅字（自动/浅/深）、低对比提示条、**「跟随主界面」开关**（恢复/取消 follow）。
- 实现为 **`skin.html` 窗内浮层**，不新开 `BrowserWindow`（避免新增窗口与 preload 面）。

### C5 · 定时提示文案
- 位置：`template.html` 的 `#remindInput` 内，**内容输入框下方**新增一行。
- 文案：有时间 → `定时提醒：H 时 M 分`（注意是中文「时/分」，非冒号）；无时间 → `全天提醒`。
- 实时：`#remindHour`/`#remindMinute` 的 `input` 事件即时更新；面板打开时初始化一次。

### C6 · 关注列表四列
- `grid-template-columns`：`62px 1fr 24px` → **`62px 1fr 56px 24px`**（`:180` 与 `:190` 两处都要改）。
- 表头 `:263` → `<div>日期</div><div>关注内容</div><div>定时</div><div></div>`。
- `render()` 中把时间从文本拆出成独立格；**删除** `:328-330` 的 `' · '+HH:MM` 拼接。
- 定时格显示：有时间 → `HH:MM`；无 → 显示 `全天`（或留空，由实现者选，需在报告里说明）。

### C7 · 关注列表新增录入
- 在 `remindlist.html` 增加录入区：日期（年/月/日）+ 内容 + 时 + 分 + 「添加」按钮。
- 提交走 `window.api.addReminder({y,m,d,hh,mm,text})`。
- **同步无需额外代码**：`add-reminder` → `broadcastReminders()` 已覆盖主窗 + 本列表窗。**验收时必须实测这一点。**

### C8 · 提醒弹窗置顶修复
- 复用分支 `electron-main.js:3132-3134` 补：重设 `setAlwaysOnTop(true,'screen-saver')` → `isVisible()` 为假则 `show()` → `moveTop()` → `focus()`。
- `:3164` `ready-to-show` 回调里 `show()` **之后**再断言一次 `setAlwaysOnTop(true,'screen-saver')` + `moveTop()`（部分环境 show 后会重置层级）。
- **不要**动主窗的 `pinned` 逻辑。

### C9 · 视觉重做的硬约束
- **纯 CSS，零新依赖**：不引 npm 包、不外链字体/图片、不新增图片资源。
- 必须保留 **light + dark 两档**，且不破坏低对比兜底机制（清晰度下限 35）。
- `[data-skin]` 皮肤层规则**必须带 `html` 前缀**（否则被源序更后的主题层反压 —— 这是 v3.0.0 四角黑边的根因）。
- 不引入显著增加重绘/内存开销的效果。

### C10 · 玻璃拟态的架构事实（决定了怎么做）
- `winBase()` 让所有窗口 `transparent:true`。Chromium 的 `backdrop-filter` **只能采样本窗口自身绘制内容，糊不到桌面像素**（桌面由 DWM 在窗口位图之上合成）。
  → 现有 `blur(26px)` 实际糊的是一片近乎平坦的页面渐变，**收益≈0**；「不像玻璃」的根因是**没有东西可糊**，不是 blur 不够大。
- Win11 `backgroundMaterial:'acrylic'` 能真糊桌面，但与 `transparent:true` 互斥且要放弃 Win10 → **本轮不动**。
- ⇒ 磨砂玻璃改走**页面自绘彩色光斑 + 分层假磨砂**：
  光斑底（2–3 个大 `radial-gradient`）→ 卡面半透明渐变 → `inset` 顶部高光 → 斜向高光带 → 多层柔和投影。
  保留 `backdrop-filter`（对窗口内元素仍有真实作用），但**不得把它当作主要手段**。
