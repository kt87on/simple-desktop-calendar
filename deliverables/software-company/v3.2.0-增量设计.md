# v3.2.0 增量设计（皮肤系统 v4 + 浮窗命名统一）

> 技术栈：Electron 31 + 纯 ES5（`var` + `'use strict'` + 中文块注释写「为什么」），无框架、无打包器。
> CSS 真身在 `template.html`（日历/桌面插件共用）与 `dock.html`（浮窗）；`build.js` 把 `lunar.min.js`+`app.js`
> 内联进 `template.html` → `calendar.html`；`electron-main.js` 为皮肤/设置唯一真相源。
> **改 `template.html`/`app.js` 必须 `node build.js`；改 `electron-main.js`/`skin.html` 等不需要。**

---

## §0 本轮范围（用户三条原文）

1. **选原生皮肤时浮窗不跟随** → 改成「四个界面全部切成该原生风格」。
2. **皮肤窗改版**：主视图两个入口（原生皮肤 / 自选图片）；点「原生皮肤」动画下拉出 6 项，
   **每项要有对应风格的迷你预览**（配色/质感/字色都要像那套皮肤）；点「自选图片」**开一个独立新窗口**
   （类似特别关注窗口），并**删掉「背景来源」「明暗」两项**。
3. **命名统一**：所有用户可见的「浮动插件」→ **「浮窗」**。

```json
"expanded": { ..., "follow": "calendar" },   // 跟随 ✓
"desktop":  { ..., "follow": "calendar" },   // 跟随 ✓
"dock":     { "style":"minimal", "bg":"image",
              "image":{"file":"dock_1789105800240.png", ...},
              "tone":"system", "follow": null }   // ← 独立，不跟随 ✗
```

- 用户 2026-09-11 05:48 给浮窗单独导入过图片 → `applySkinSet` 的 **C2「手调即豁免跟随」**

## §2 冻结契约（先冻结再并行编码，勿各自发挥）

### C1 · 「原生皮肤」= 全局统一（需求 1 核心）

新增 IPC action（**复用既有 `skin-action` 通道，不改 preload**）：

```
渲染层：api.skinAction('apply-native-style', { style: '<default|minimal|glass|neu|tech|warm>' })
```

主进程处理（`skin-action` 新增分支）：

```
对 4 个面 n ∈ {calendar, expanded, desktop, dock} 依次执行：
  skin.surfaces[n].style  = normStyle(payload.style)
  skin.surfaces[n].bg     = 'native'
  skin.surfaces[n].image  = null
对 expanded / desktop / dock 额外：skin.surfaces[n].follow = 'calendar'
收尾（与 applySkinSet 末尾一致）：
  recomputeTheme(); saveSettings(); pushThemeToAll(); pushSkinToAll();
  pushSkinConfigState(); refreshTrayMenu();
```

- **不删盘上图片文件**（`userData/skins/*` 保持），仅解除配置引用 —— 用户之后进「自选图片」可重新指定。
- 非法 `style` → 回落 `'default'`（`normStyle` 已有语义），**不得写脏数据**。
- 为什么不做 4×3 次 `skinSet`：会触发 12 次 `saveSettings`+4 轮推送，既慢又可能中途被读盘中。
  单次原子写入是唯一正确的口径。

### C2 · 「自选图片」= 独立新窗口（需求 2）

新增 IPC action：

```
渲染层：api.skinAction('open-custom', { surface: 'calendar' })   // surface 可省，默认 calendar
渲染层：api.skinAction('close-custom')                            // 新窗口的 ✕ / Esc
```

主进程：
- 新增 `skinCustomWin`（与 `skinWin` 同级变量），新增 `openSkinCustomWindow(initialSurface)`：
  - 单例：已存在则 `focus()` + `pushSkinConfigState()` + 返回。
  - `winBase({ width: 500, height: 660, resizable: false, alwaysOnTop: true, skipTaskbar: true, show: false })`，
    `setAlwaysOnTop(true,'screen-saver')`，居中，`loadFile('skincustom.html',{ query:{ theme: baseTheme(), surface: initialSurface||'calendar' } })`，
    `once('ready-to-show')` 内 `show()` + `pushSkinConfigState()`，`on('closed')` 置 null。
- `pushSkinConfigState()` 改为**同时**发 `skinWin` 与 `skinCustomWin`（同一份 `skinConfigState()`）。
- `skin-import-result` 回传（`choose-file` 分支）**同时**发 `skinWin` 与 `skinCustomWin`。
- `skin-action` 的 `close` 分支：**保持只关 `skinWin`**；`close-custom` 关 `skinCustomWin`。
- 退出清理（`electron-main.js:3795` 附近）：补 `skinCustomWin` destroy。

### C3 · `skin.html` 主视图结构（需求 2）

- 顶部保留 `#head`（标题「皮肤设置」+ ✕）。
- `#body` 内两个入口按钮（都是整行可点）：
  1. `#entryNative`「原生皮肤」—— 点击**动画展开/收起** `#nativeList`（6 行）。带 chevron 旋转。
  2. `#entryCustom`「自选图片」—— 点击 `api.skinAction('open-custom', {surface:'calendar'})`。
- `#nativeList` 6 行 `button.style-row[data-style]`，**每行左侧是该风格的迷你预览**，右侧/居中为风格名。
  - 预览必须是**该风格的真实观感**（配色 + 质感 + 字色），数据取自 `template.html:263-521` 的 6 个风格块。
  - 预览条建议约 150×30（含圆角/描边/内部 mini 元素），行高约 46。
  - 6 风格：`default` 默认 / `minimal` 极简 / `glass` 玻璃拟态 / `neu` 新拟态 / `tech` 科技感 / `warm` 温润拟物。
    - tech = 赛博：深底 + 青(#06b6d4)/品红霓虹辉光 + 网格 + 切角；
    - glass = 玻璃拟态：半透明白洗 + 斜向光泽带 + 模糊感；
    - neu = 新拟态：同底色双向柔影（凸起）+ 内凹控件；
    - warm = 温润拟物：暖米色 + 柔和边缘；
    - minimal = 极简：去装饰、纯净；
    - default = 默认：浅灰扁平。
- **点击某行** → `api.skinAction('apply-native-style', {style:X})`。
- **选中态高亮**：仅当 `resolved.calendar.style === X` **且** `resolved.calendar.bg === 'native'` 时该行 `.active`。
- **「自选图片」入口**：若 4 个面中**任一** `bg === 'image'`（取 `S.skin.surfaces[*]`），入口加 `.active`
  以示「当前有自选图片在用」。
- 主视图**不再有任何** per-surface 控件（界面选择器/背景来源/明暗/文字/清晰度/透明度/取景/跟随开关）
  → 全部迁至 `skincustom.html`。
- 窗口高度由 C4 定为 520×640；**`#body` 必须可纵向滚动**（`#nativeList` 展开后可能超出）。

### C4 · 窗口尺寸

- `skinWin`：**520×640**（原 620）。`resizable:false` 保持。
- `skinCustomWin`：**500×660**，`resizable:false`。

### C5 · `skincustom.html` 内容（需求 2）

- 新文件，**结构与视觉沿用现 `skin.html` 的卡片范式**（`#card/#head/#body`，`--paper/--ink/--accent` 等
  L1/L2/L3 token 原样搬，保持同一套设计语言），标题「自选图片」，✕ 走 `api.skinAction('close-custom')`。
- 界面分段 `#surfaceTabs`：`日历界面` / **`浮窗界面`** / `桌面插件界面` / `放大界面`（`data-surface` = `calendar`/`dock`/`desktop`/`expanded`）。
- 保留的区块（顺序）：
  1. `#followRow` 跟随主界面开关（**仅 `dock/desktop/expanded` 显示**；`FOLLOWABLE = {expanded:1,desktop:1,dock:1}` 不变）
  2. `#imageSection` 图片取景：`#dropZone` + `#cropWrap/#cropBox/#cropImg` + `#cropEmpty` + `#cropTip` + 图片不透明度滑杆
  3. `#textSection` 文字明暗（自动/深字/浅字）+ `#warnTip` 低对比提示
  4. `#claritySection` UI 清晰度（`#clarityAuto` + `#clarityRange`）
  5. 透明度 `#opacityRange`
- **删除**：`#bgGrid` 背景来源整段、`#toneSection/#toneGrid/#toneTip` 明暗整段。
- 初始 surface 从 `?surface=` 取，缺省 `calendar`。
- 写操作仍走 `api.skinSet(surface, field, value)`；订阅 `api.onSkinConfigState` / `api.onSkinImportResult`。
- **`bg` 如何回到原生**（因为删了背景来源）：靠主窗口选原生皮肤（C1）或本窗口的「跟随主界面」开关。
  这是用户明确要求删的，**不要偷偷加回**。

## §4 验收标准

1. **选任意原生风格 → 日历 / 浮窗 / 桌面插件 / 放大窗口四处外观一致**（浮窗哪怕此前独立、有自选图片，也要被覆盖）。
2. 皮肤窗主视图只有两个入口；点「原生皮肤」有动画展开，6 行每行有**可辨的该风格迷你预览**（含字色）。
3. 点「自选图片」→ **独立新窗口**（不是窗内浮层）；该窗口内**找不到**「背景来源」「明暗」两项。
4. 新窗口内改任一界面设置 → 即时生效并持久化；重开窗口回显正确。
5. 全仓用户可见处**不再出现「浮动插件」**，统一为「浮窗」。
6. `npm run check` 六闸门全绿（断言数按新结构更新后）。
7. 深色/浅色主题下，皮肤窗与新窗口均正常（不出现 v3.1.0 那类黑边/不可读）。
