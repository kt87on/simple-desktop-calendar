# v3.3.0 造型覆盖层预览 · 说明

本目录六张 `v3.3.0-覆盖层-*.png` 由 `shape-preview-workbench.js` 生成，把浮窗的
**窗口矩形 / 卡片盒 / 圆角缺口**三层几何**显式画出来**，让「轮廓 ↔ 窗口」之间的绘制越界**在预览里就能看见**。

## 为什么要有这一版（X1 / X2 连续两轮溜过预览的根因）

旧工装只画「卡片盒」（`.wg` 的 156×64 / 150×150 …），**没有「窗口矩形」与「圆角缺口」两个概念**。
而真实浮窗是「窗口 > 卡片盒」（四周留 `pad`）＋「卡片盒的四个圆角是透明的」——
于是这两片区域**在旧预览里根本不存在**，任何落在那里的不透明绘制
（越界的 `box-shadow` 外投影、窗口/`body` 的底色）**只在真机上显形**。
⇒ 修 X1/X2 只修了症状；把这两片区域画进预览，才能防下一轮再犯。

## 图例（每张图都带同样一份）

| 标记 | 含义 |
|---|---|
| 红虚线框 + 淡红底 | **① 窗口矩形** `winW×winH` —— **硬裁边界**，落在它外面的绘制会被裁掉 |
| 蓝虚线框 | **② 卡片盒** = 窗口 − 四边 `pad`（**逐边算，不是等距**） |
| 红色块（四角） | **③ 圆角缺口** = 「方形角 − 四分之一圆」，共 4 处 |

第三层不能省：**「圆角外面是直角框」这类报障就发生在这里**，而且它**与 `pad` 是否 >0 无关**。
⑥ 那一张的第三格是真实对照：**窗口 == 卡片（pad 全 0）时缺口照样在**。

> **⑥ 的对照格证明了什么**：它把「窗口与卡片完全重合、四边 `pad` 全 0」这一极端情形画了出来 ——
> 此时**没有任何缝隙**（`pad` 判据会判定「无问题」），**但四个角的圆角缺口依然存在**。
> 所以「圆角外面是直角框」**不是缝隙造成的**，而是**窗口矩形本身是直角**造成的；
> 只靠 `pad` 判据必然漏判，**必须看第 ③ 层才能指认**。

## 六张图一览

| 图 | 造型 | 窗口 | 卡片盒 | pad(L/T/R/B) | R | 缺口·单角 | 缺口·四角 |
|---|---|---|---|---|---|---|---|
| `①像素方屏` | pixel | 180×88 | 156×64 | 12/12/12/12 | 14 | 42.06 px² | 168.25 px² |
| `②虹彩流光` | rainbow | 140×68 | 116×44 | **24/24/0/0** † | 13 | 36.27 px² | 145.07 px² |
| `③极简圆环` | ring | 174×174 | 150×150 | 12/12/12/12 | 75（50%） | 1207.14 px² | 4828.54 px² |
| `④翻页时牌` | flip | 220×128 | 196×104 | 12/12/12/12 | 0 | 0 | 0 |
| `⑤绘本台钟` | toon | 182×198 | 158×174 | 12/12/12/12 | 0 | 0 | 0 |
| `⑥圆角卡片` | rect | 116×50\* | 114×48 | **2/2/0/0** | 10 | 21.46 px² | 85.84 px² |

\* `rect` 的窗口高在注册表里是 `winH: 0`，真身 =「任务栏高 clamp 40~56」，表内取 50 作代表值。

† `rainbow` 的 pad 在 **Y1** 由 `12/12/12/12` 改为 **`24/24/0/0`**（`winW/H` 仍 140/68、**卡片仍 116×44**）；
左/上 24 是 inset 光晕的容纳区、右/下 0 ⇒ 卡片右/下沿贴死窗口，用于「压任务栏上沿 + 贴工作区右沿」。
本图为 **Y1 后重出**（旧图备份于 `.tmp-diag/shape-spec-old/②虹彩流光-pre-Y1.png`，保证交付目录内不留错图）。

两点值得注意：
- **`rect` 与 `rainbow` 的 pad 都不是等距**：两者 `padR/padB = 0` ⇒ 卡片右/下沿贴死窗口右下沿
  （`rect` 自始如此；`rainbow` 由 **Y1** 起如此，左上 24 为 inset 光晕的容纳区）。所以卡片盒
  **必须逐边算**；按等距画会把这两款画错。
- **`flip`/`toon` 的 `--dock-radius` 是 0**（卡片盒整体不可见，视觉全在内层承担）⇒ 没有圆角缺口，也因此
  从来不受这类报障影响。

## 角部缺口面积（公式）

```
单角 = R² · (1 − π/4) ≈ 0.214602 · R²
四角合计 = 4 · R² · (1 − π/4)
```

`R` 取该造型的 `--dock-radius`；`ring` 是 `50%` ⇒ `R = cardW/2`；`flip`/`toon` 是 `0` ⇒ 无缺口；
`rect` 的 `R = --r-md = 10px` ⇒ 四角 ≈ **85.84 px²**。

## 成框判据（勿单独使用）

- **完整的 pad 环**需要**四边 `pad` 同时 > 0**。
  `padL+padR>0 && padT+padB>0` 只说明「横竖各有缝」，**不等于**「四边都有缝」。
- 而 pad 判据的**真正盲区**是「窗口 == 卡片」：那时四边 `pad` 全 0，缺口却依然可见。
  所以**第 ③ 层（圆角缺口）才是这类报障的通用指认层**，pad 判据只是它的一个特例。
- **红块 ≠ 缺陷**：第 ③ 层标的只是「**窗口矩形是直角、此处不在卡片圆角内**」这一**几何事实**；
  它是不是缺陷，取决于该处**有没有越界的不透明绘制**（如 `box-shadow` 外投影）。
  `ring`（`R = 50%`，四角红块就是**圆形本体**）、`flip`/`toon`（`R = 0`，无红块），
  以及 X2 后的 `rainbow`/`ring`（无外投影）⇒ **缝隙/红块存在 ≠ 缺陷**。

## 开关注册

右上角单选：**`窗口层`（默认，三层全开）** / `仅卡片层`（只隐藏窗口矩形，保留卡片盒 + 圆角缺口）。
切换**只切覆盖层的显示，不改任何造型取值** —— 避免变成两个真源。
（六张归档图为默认态，即「窗口层」。）

## 真源与口径漂移自检

- 造型取值**只允许一个真源 = `dock.html` 的 `DOCK_SHAPE_VARS`**；窗口/内边距的真源 = `electron-main.js` 的 `DOCK_SHAPES`。
  本工装不再各自硬编码一遍：阴影值集中在 `DOCK_SHADOW` 里插值进 CSS。
- 生成时**回读两个真源文件**：逐值核对窗口/`pad`/阴影，并把**真源行号**写进每行的标注
  （`注册表 ← electron-main.js:NNN`、`--dock-shadow ← dock.html:NNN`，行号每次生成时现算）。
  任何不一致 ⇒ 图顶部红条 + stdout 告警。
  > 本说明**刻意不抄行号**，否则说明自身就会随改动漂移；行号请看各图行内标注。
- 该自检在第一次生成时就**抓到了一处真漂移**：工装原把 ⑥ 显示为「圆角矩形」，而注册表里的名字是
  「**圆角卡片**」。已按注册表口径统一（造型中文名同样只允许一个真源）。

## 坐标口径（归档图一律用基础值，不乘 `s`）

- 六张归档图画的是**基础尺寸**（注册表 `winW×winH` 与逐边 `pad` 的原始值），**不乘缩放 `s`**，也不标任何 `×s` 数值 ——
  与 `dock.html` 的 CSS 视口、`pushDockSize` 发**基础值**的口径一致，避免出现「两份尺寸」。
- **真机陷阱（w-f-frame 实测）**：窗口 DIP 高会被**吸附到偶数** —— `pixel` 实测 54/70/142（`round(88×s)` 理想 53/70/141）、
  `ring` 104/**140**/278（理想 104/**139**/278）。方向只会让**缝隙变大**（对 X2 是安全方向）；
  但**若有人另在图上标 `基础值×s`，必须注明「实际落地取偶数」**，否则会与真机差 1px。
- **dpr 陷阱（同上）**：`DevicePixelRatio = 屏幕缩放 × zoom`，**不能**拿 dpr 反推屏幕缩放；正确式 `scr = dpr / s`。

## 复现

```bash
cd <repo>
node deliverables/design/v3.3.0-shape-spec/shape-preview-workbench.js
```

生成：预览页 + 六张分款出图页到 `%TEMP%`；若 Edge 在默认路径则同时用
`--headless=new --window-size=<W>,<H> --force-device-scale-factor=2` 直接出图到本目录
（`--headless=new` 下 `--window-size` 是精确的：`400×300 → 400×300`，×dsf2 → `800×600`）。
Edge 不在默认路径时只生成页面并打印命令，不阻断。
（本目录既有 PNG 一律未改动；本次只新增 `v3.3.0-覆盖层-*.png` 六张。）
